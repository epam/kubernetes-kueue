# config/

Kustomize manifests for deploying Kueue. These are the source-of-truth manifests used by both the Kustomize install path and as the basis for the Helm chart.

## Structure

```
config/
├── components/          # Reusable kustomize components
│   ├── crd/             # CRD base manifests (generated by controller-gen)
│   ├── manager/         # Deployment, ServiceAccount, controller config
│   ├── rbac/            # ClusterRole, ClusterRoleBinding, roles for leader election and secrets
│   ├── webhook/         # ValidatingWebhookConfiguration, MutatingWebhookConfiguration, Service
│   ├── certmanager/     # cert-manager Certificate + Issuer resources
│   ├── internalcert/    # Self-signed TLS secret (used when cert-manager is not installed)
│   ├── visibility/      # APIService registrations (v1beta1, v1beta2) for the Visibility API
│   ├── visibility-apf/  # FlowSchema + PriorityLevelConfiguration for the Visibility API server
│   ├── prometheus/      # ServiceMonitor for Prometheus scraping
│   └── kueueviz/        # KueueViz frontend + backend Deployment, Service, ClusterRole, Ingress
├── default/             # Default installation overlay — composes all standard components
├── dev/                 # Development overlay — extra logging, debug flags
├── alpha-enabled/       # Overlay with all alpha feature gates enabled
├── prometheus/          # Prometheus-only overlay (just the ServiceMonitor)
├── visibility-apf/      # Visibility APF-only overlay
└── kueueviz/            # KueueViz-only overlay (patches Ingress and ConfigMap)
```

## Usage

```bash
# Standard install
kubectl apply -k config/default

# With cert-manager
kubectl apply -k config/default
kubectl apply -k config/components/certmanager

# Development
kubectl apply -k config/dev
```

## Relationship to Helm

The `charts/kueue/` Helm chart is derived from these manifests. The `hack/tools/yaml-processor/` tool is used during chart generation to translate Kustomize patches into Helm template variables.
